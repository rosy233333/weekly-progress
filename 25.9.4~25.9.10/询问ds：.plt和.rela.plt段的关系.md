# 询问：在使用了PIC的共享库中，是否会有存在.plt段却没有.rela.plt段的情况？

这是一个非常好的技术问题。

简短的回答是：**在正常情况下，一个使用了PIC（位置无关代码）的共享库（.so）中，绝对不会有存在 `.plt` 段却没有 `.rela.plt` 段（或其32位等价物 `.rel.plt`）的情况。这两个段是紧密耦合、相互依存的。**

下面进行详细解释：

### 1. 角色和职责

首先，我们需要理解这两个段在动态链接过程中的作用：

* **`.rela.plt`** （RELocation A with Addend for PLT）：
  * 这是一个**重定位表**，它包含了所有需要被解析的**函数符号**的信息。
  * 每个条目（例如一个 `R_X86_64_JUMP_SLOT` 类型的重定位）告诉链接器：“在运行时，请找到符号 `printf` 的真实地址，然后把这个地址写入到 `.got.plt` 段中偏移量为 `X` 的位置”。
  * 它本质上是 `.plt` 段的需求列表。

* **`.plt`** （Procedure Linkage Table）：
  * 这是一小段**代码存根（stubs）**。每个需要被动态解析的函数（如 `printf`, `malloc`）在 `.plt` 中都有一个对应的条目。
  * 当你的代码第一次调用 `printf@plt` 时，实际是跳转到 `.plt` 中为 `printf` 准备的存根代码。这段代码会通过 `.got.plt` 间接跳转。
  * **第一次调用时**，`.got.plt` 中的地址会指向 back-tracking 代码，促使动态链接器（ld-linux.so）介入。链接器查找 `printf` 的真实地址，将其填入 `.got.plt` 中对应的位置，然后执行该函数。
  * **后续调用**时，通过 `.plt` 存根的间接跳转会直接指向已解析好的 `printf` 地址，几乎没有开销。

* **`.got.plt`** （Global Offset Table for PLT）：
  * 这是一个**数据表**，存储着函数的实际地址。它是 `.plt` 段要跳转去的目标地址的“指针数组”。

### 2. 它们如何协同工作

这三者的关系可以概括为：
**你的代码 -> `.plt` -> `.got.plt` (初始状态) -> 动态链接器 -> 解析函数地址并回填至 `.got.plt` -> 后续调用直接跳转到真实函数**

而 `.rela.plt` 就是告诉动态链接器 **“需要为哪些函数做回填”** 以及 **“回填到 `.got.plt` 的哪个位置”** 的关键元数据。

### 3. 为什么不能没有 `.rela.plt`

假设一个共享库有 `.plt` 段（即存在函数调用存根），但却没有 `.rela.plt` 段，这意味着：

1. 动态链接器在加载这个库时，完全不知道 `.plt`/.`got.plt` 中哪些项需要被解析。
2. `.got.plt` 中的函数地址指针将始终保持为初始状态（指向链接器的解析逻辑）。
3. 任何通过 `.plt` 进行的函数调用都会陷入无限循环：跳转到 `.plt` -> 跳转到 `.got.plt` -> 跳转回链接器 -> 链接器发现没有需要它处理的重定位条目 -> 无法修复地址 -> 下一次调用继续循环。

这最终会导致程序在运行时发生段错误（Segmentation Fault）或非法指令等严重错误。

### 结论与例外情况

因此，**`.plt` 的存在必然意味着 `.rela.plt` 的存在**。它们是动态链接机制中不可分割的两个部分。你可以使用 `readelf` 工具来验证这一点：

```bash
readelf -S /path/to/yourlib.so | grep -E '(plt|rela)'
```

输出你会同时看到 `.plt` 和 `.rela.plt` 这两个段（section）。

**理论上唯一的“例外”：**

* 如果一个共享库**完全没有需要外部解析的函数调用**（例如一个极其简单的、只使用静态数据的库），那么它可能既没有 `.plt` 也没有 `.rela.plt`。但这不属于“有.plt却没有.rela.plt”的情况。
* 如果一个库的所有函数调用都被**静态链接**进去了（虽然对于共享库来说这很罕见且不符合其设计初衷），或者被某种高度优化的链接时优化（LTO）完全内联和消除了，但也极难做到只消除重定位表而保留过程链接表。

所以，在实践中，如果你发现一个共享库看起来有 `.plt` 却没有 `.rela.plt`，那更可能是你使用的分析工具（如 `objdump`）的显示问题，或者该文件已经损坏、被故意篡改，而不是一个有效的、可正常工作的ELF文件。
